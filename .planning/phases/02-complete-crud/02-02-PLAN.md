<task type="auto">
  <name>Task 1: Add file upload and download to documents API</name>
  <files>src/app/api/documents/route.ts, src/app/api/documents/[id]/route.ts</files>
  <action>
    Update the documents API to handle file upload via base64 encoding (stored in the `fileUrl` column as a data URI — no external storage needed for v1):

    **POST /api/documents (update existing):**
    - Accept multipart form data OR JSON body with base64 file
    - For JSON approach: accept `{ propertyId, name, type, file: "base64string", mimeType, fileSize }`
    - Store the base64 data as a data URI in `fileUrl`: `data:{mimeType};base64,{base64data}`
    - Set `fileSize` and `mimeType` from the upload

    **GET /api/documents/[id] (update existing):**
    - Currently only has DELETE. Add GET that returns the document record including the base64 fileUrl
    - Add a query param `?download=true` that returns the raw file with proper Content-Type and Content-Disposition headers (decode base64 and stream as binary)

    **DELETE /api/documents/[id] (keep existing):**
    - Already works, no changes needed

    Do NOT use external file storage (S3, Cloudflare R2) — base64 in Postgres is fine for v1 with property documents. The schema already has `fileUrl: text` which can hold data URIs.
  </action>
  <verify>npm run build passes. API compiles without errors.</verify>
  <done>Documents can be uploaded as base64, stored in DB, and downloaded with proper MIME types.</done>
</task>

<task type="auto">
  <name>Task 2: Wire up file upload in documents page</name>
  <files>src/app/(app)/documents/page.tsx</files>
  <action>
    Update the documents page to support actual file upload:

    1. Add a file input (`<input type="file" accept=".pdf,.jpg,.jpeg,.png,.doc,.docx">`) to the upload form
    2. On file selection, read the file as base64 using FileReader
    3. POST to /api/documents with: propertyId, name (default to file name), type (document type select), file (base64), mimeType (from file.type), fileSize (from file.size)
    4. Display uploaded documents in the list with:
       - File name and type
       - Property association
       - File size (formatted: KB/MB)
       - Upload date
       - Download button that opens GET /api/documents/[id]?download=true
       - Delete button (already exists)
    5. Add a file size limit check on the client side (max 10MB) — show error if file too large

    Keep the existing property filter functionality.
  </action>
  <verify>npm run build passes. Documents page has a working file upload form.</verify>
  <done>Users can upload documents (PDF, images), see them listed with download links, and delete them. File size limited to 10MB on client.</done>
