1. **Add new columns to the `properties` table in schema.ts:**

After the existing `notes` field, add:

```typescript
// Registration details
dastavejNo: text("dastavej_no"),
registrationDate: timestamp("registration_date"),
stampDuty: numeric("stamp_duty", { precision: 12, scale: 2 }),
registrationCharges: numeric("registration_charges", { precision: 12, scale: 2 }),

// Ownership
ownership: text("ownership"),
```

**Column details:**
- `dastavej_no` — text, nullable. Stores the deed/document registration number (e.g., "1870/2006", "6948/2015")
- `registration_date` — timestamp, nullable. The date the property was officially registered (may differ from purchase date)
- `stamp_duty` — numeric(12,2), nullable. Stamp duty amount paid (e.g., 9930, 120100)
- `registration_charges` — numeric(12,2), nullable. Registration charges paid (e.g., 1950, 24625)
- `ownership` — text, nullable. Free-form ownership description (e.g., "50% Siva, 50% NMP", "100% Siva"). Using text instead of a structured table because ownership descriptions are informal and varied.

**Note:** Total Cost is NOT stored in the database — it's computed as `purchasePrice + stampDuty + registrationCharges` on the frontend/API. This avoids data inconsistency.

2. **Push schema changes to Neon:**

```bash
npm run db:push
```

This uses Drizzle's schema push to apply changes to the Neon database without formal migrations (established pattern for this project).

3. **Do NOT modify the Property type exports** — they auto-infer from the schema via `$inferSelect` and `$inferInsert`, so the new fields are automatically available.
