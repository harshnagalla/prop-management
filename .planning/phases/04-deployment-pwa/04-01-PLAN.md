<task type="auto">
  <name>Task 1: Add PWA service worker with @serwist/next</name>
  <files>next.config.ts, src/app/sw.ts, src/app/layout.tsx, package.json</files>
  <action>
    Install and configure @serwist/next for Next.js 15 PWA support:

    1. Install dependencies: `npm install @serwist/next && npm install -D serwist`

    2. Create `src/app/sw.ts` — the service worker entry point:
       ```
       import { defaultCache } from "@serwist/next/worker";
       import type { PrecacheEntry, SerwistGlobalConfig } from "serwist";
       import { Serwist } from "serwist";

       declare global {
         interface WorkerGlobalScope extends SerwistGlobalConfig {
           __SW_MANIFEST: (PrecacheEntry | string)[] | undefined;
         }
       }

       declare const self: ServiceWorkerGlobalScope;

       const serwist = new Serwist({
         precacheEntries: self.__SW_MANIFEST,
         skipWaiting: true,
         clientsClaim: true,
         navigationPreload: true,
         runtimeCaching: defaultCache,
       });

       serwist.addEventListeners();
       ```

    3. Update `next.config.ts` to wrap with withSerwist:
       ```
       import withSerwistInit from "@serwist/next";

       const withSerwist = withSerwistInit({
         swSrc: "src/app/sw.ts",
         swDest: "public/sw.js",
         disable: process.env.NODE_ENV === "development",
       });

       export default withSerwist({ serverExternalPackages: ["@neondatabase/serverless"] });
       ```

    4. Verify `public/manifest.json` already links correctly in layout.tsx metadata
    5. Ensure `public/sw.js` is in `.gitignore` (it's a build artifact)

    Do NOT create a custom caching strategy — use Serwist's `defaultCache` which handles pages, static assets, and API routes with sensible defaults.
  </action>
  <verify>npm run build passes. public/sw.js is generated during build.</verify>
  <done>Service worker generated on build, PWA is installable, offline caching works for static assets.</done>
</task>

<task type="auto">
  <name>Task 2: Deploy to Vercel</name>
  <files>vercel.json (if needed)</files>
  <action>
    Deploy the application to Vercel using the CLI:

    1. Check if Vercel CLI is installed: `npx vercel --version`
    2. Run `npx vercel --yes` to deploy (auto-detects Next.js, creates project)
    3. If auth gate (not logged in): stop and create dynamic checkpoint for user to run `npx vercel login`
    4. After deployment succeeds, set environment variables:
       - `npx vercel env add DATABASE_URL production` — use the Neon connection string from .env.local
       - `npx vercel env add AUTH_SECRET production` — use the auth secret from .env.local
       - `npx vercel env add GOOGLE_AI_API_KEY production` — use the API key from .env.local
       - `npx vercel env add NEXT_PUBLIC_APP_URL production` — set to the Vercel deployment URL
       - `npx vercel env add AUTH_TRUST_HOST production` — set to "true" for NextAuth on Vercel
    5. Redeploy to production with env vars: `npx vercel --prod --yes`
    6. Verify production deployment loads correctly: `curl -s -o /dev/null -w "%{http_code}" {deployment-url}`

    If Vercel CLI is not installed, use `npx vercel` which auto-installs it.
    If any env var command fails with interactive prompt, read the value from .env.local and pipe it: `echo "value" | npx vercel env add NAME production`
  </action>
  <verify>Production deployment returns HTTP 200. Vercel dashboard shows the project.</verify>
  <done>App is live on Vercel with all environment variables configured. Production URL accessible.</done>
</task>
