<task type="auto">
  <name>Task 1: Define Zod schemas and migrate to generateObject</name>
  <files>src/lib/ai/gemini.ts</files>
  <action>
1. Add `import { z } from "zod"` and `import { generateObject } from "ai"` (replace generateText import).

2. Install zod: `npm install zod` (required for generateObject schemas).

3. Define two Zod schemas at module level:

**billDataSchema:**
- amount: z.number().optional().describe("Total bill amount")
- date: z.string().optional().describe("Date in YYYY-MM-DD format")
- category: z.enum(["electricity", "water", "municipal_tax", "maintenance", "insurance", "repair", "legal", "other"]).optional().describe("Bill category")
- vendor: z.string().optional().describe("Company or vendor name")
- referenceNumber: z.string().optional().describe("Bill or receipt number")
- propertyHint: z.string().optional().describe("Any address or property identifier visible on the bill")
- lineItems: z.array(z.object({ description: z.string(), amount: z.number() })).optional().describe("Itemized line items")

**spreadsheetDataSchema:**
- properties: z.array(z.object({
    name: z.string().describe("Property name or identifier"),
    address: z.string().optional(),
    type: z.enum(["residential", "commercial", "industrial", "land", "mixed"]).optional(),
    purchasePrice: z.number().optional(),
    currentValue: z.number().optional(),
    monthlyRent: z.number().optional(),
    tenantName: z.string().optional(),
    area: z.number().optional().describe("Area in sqft")
  })).optional()

4. Replace both functions to use `generateObject`:
- `const { object } = await generateObject({ model: google("gemini-2.0-flash"), schema: billDataSchema, messages: [...] })`
- Return `object` directly (no JSON.parse needed)
- Keep the same function signatures and return types for API compatibility

5. Improve the bill extraction prompt:
- Add explicit instructions for Indian utility providers (Torrent Power, UGVCL, DGVCL for electricity; AMC/Ahmedabad Municipal Corporation for municipal_tax; GWSSB for water)
- Add instructions for reading amounts in Indian numbering (lakhs, crores)
- Add instruction to look for GSTIN, consumer number as referenceNumber
- Tell the model to extract dates from any format (DD/MM/YYYY common in India) and convert to YYYY-MM-DD

6. Improve the spreadsheet extraction prompt:
- Add instruction to strip ₹ symbol, commas, and "Rs." prefix from amounts
- Add instruction to normalize property types to the enum values

<task type="auto">
  <name>Task 2: Add retry logic and improve API error handling</name>
  <files>src/lib/ai/gemini.ts, src/app/api/ai/extract/route.ts</files>
  <action>
1. In gemini.ts, wrap each generateObject call in a retry helper:
- Create a local `async function withRetry<T>(fn: () => Promise<T>, maxRetries = 2): Promise<T>` at module level
- On failure, retry up to 2 times (3 total attempts) with 1s delay between retries
- On final failure, throw a descriptive error with the original error message
- Apply withRetry to both extractBillData and extractSpreadsheetData's generateObject calls

2. In the API route (route.ts), improve error handling:
- Catch specific error types: if error.message includes "rate limit" or "429", return 429 with "AI service rate limited, please try again in a moment"
- If error.message includes "invalid" or "schema", return 422 with "Could not extract structured data from this document"
- Default: return 500 with "Failed to extract data from document"
- Log the full error for debugging but return user-friendly messages

3. Add file size validation in the API route:
- Estimate base64 size: if file.length > 20_000_000 (roughly 15MB decoded), return 400 with "File too large. Maximum 15MB."
